KNOWLEDGE CARD / 知识卡

车辆：Nova Carter 与自定义平面载台

模型知识与来源，按需阅读。未发布的实验文件以“本地核验记录”标识；这些数值不构成实机规格。

图解见 Isaac 机器人与两种底盘对照；AOR-013 的简化扫地底盘单列于 VACUUM.md，不与本卡的旧车共用参数。

“车辆”在本地不是一个固定模型。Vehicle–H1 用 Isaac Nova Carter；早期 Vehicle–MicroDuck 用 MuJoCo 自定义载台。前者是差速轮控制，后者有三个平面关节和速度执行器。两者均不能直接称作 OOMWOO 扫地机，也不能沿用对方的质量、轮距或状态维度。

Isaac Nova Carter

来源为 NVIDIA Isaac 资产根的 /Isaac/Robots/NVIDIA/NovaCarter/nova_carter.usd。具体路径和控制参数见 waypoints.json本地核验记录：Isaac/configs/waypoints.json 与 vehicle_h1_assisted_mobility_v0.json本地核验记录：Isaac/configs/vehicle_h1_assisted_mobility_v0.json。本轮核对配置和控制代码，USD 解析后的依赖层版本、完整 joint/link/驱动数量与资产许可证未知；控制源码哈希已纳入 inventory本地核验记录：docs/robots/runs/20260905-aor012-inventory-01/inventory.json。不把未读取的 USD 声称为开源模型。

配置的驱动关节是 joint_wheel_left、joint_wheel_right；控制器使用轮半径 0.14 m、轮距 0.4132 m。这是当前配置值，未通过 USD 几何测量复核。DifferentialController 将车体 [v, wz] 转成两轮角速度，再由 apply_wheel_actions 施加，标准理想差速关系为 ωL=(v−wz·b/2)/r、ωR=(v+wz·b/2)/r；实际前进符号由该模型的轮轴与 API 约定共同决定。入口：run_waypoints.py本地核验记录：Isaac/scripts/run_waypoints.py、run_rendezvous.py本地核验记录：Isaac/scripts/run_rendezvous.py。

状态来自世界基座位姿/速度，导航用世界 XY 目标和 yaw；线速度 m/s，角速度/轮速 rad/s，方向由身体朝向转换。单独 waypoint 的步长是 0.0166666667 s、命令速度上限 0.40 m/s；Vehicle–H1 配置是 0.005 s、0.80 m/s。不能把命令上限当作测得速度。实际完整 articulation 状态维度未知，MuJoCo 的 nq/nv/nu 不适用。

既有技能是驱动、转向、会合、稳定等待/停止，并参与 AOR 的辅助移动计划。原始协作运行本地核验记录：Isaac/output/vehicle_h1_assisted_mobility_run_20260903_213710.json 中 Carter 的任务运动是物理控制，H1 的搭乘是另一张卡说明的代理。没有物理承载 H1 的证据，也没有在本任务证明激光雷达/摄像头参与避障。资产中可能存在传感器，不等于控制链使用了它。

MuJoCo 自定义 Vehicle–MicroDuck v0

模型由 vehicle_microduck_demo.py本地核验记录：MuJoCo/scripts/vehicle_microduck_demo.py 的 build_vehicle_spec() 在内存里创建，包含 Pollen 的 scene_ball.xml。没有独立厂家车型或固定 vehicle XML；该 Python 文件的 SHA-256 是本地模型定义的版本标识，见 inventory 的 assets。项目自研许可需按主仓库发布范围处理；Pollen 资产许可另见 Duck 卡。

属性实际定义或提取
身体vehicle，显式质量 5 kg，惯性 [0.18, 0.28, 0.32] kg·m²；是设计参数，不是实车测量
关节vehicle_x、vehicle_y 为沿基准 X/Y 的 slide；vehicle_yaw 绕 Z 的 hinge
输入vehicle_drive_x、vehicle_drive_y：m/s，范围 ±0.40；vehicle_drive_yaw：rad/s，范围 ±1.0
力限制三执行器分别 ±80 广义力单位：slide 为 N，yaw 为 N·m
车体状态贡献3 个 qpos、3 个 qvel、3 个 ctrl；从组合的具名关节/执行器逐项提取，未单独生成一台车模型
已加载组合Duck + 球 + 载台，BAM 路径：nq=31, nv=29, nu=17；key 为 vehicle_duck_ball_bam

四个轮子是不可碰撞的视觉几何，牵引不来自轮地接触。载台位置由执行器和物理积分变化，但固定 Z/roll/pitch 的三个平面关节使其成为简化动力学平台，不是完整汽车或扫地机。

公共接口为 set_velocity(vx, yaw_rate)、stop()、get_state()、reset()；身体前向命令根据观测 yaw 转成世界 X/Y 执行器目标。v0 包装器限幅 0.32 m/s、0.75 rad/s，比上表执行器硬限幅更窄。get_state 与任务记录报告位置、朝向、速度和控制命令；reset 是初始化操作，不应算作任务运动。

duck_ride_weld 在构建时关闭，任务中可切换来逻辑附着 Duck。v0 的 BOARD/RIDE/ALIGHT 因而不能证明无辅助爬上爬下载台。能力与限制见 VEHICLE_MICRODUCK_V0.md本地核验记录：MuJoCo/VEHICLE_MICRODUCK_V0.md。带升降的 vehicle_microduck_lift_demo.py本地核验记录：MuJoCo/scripts/vehicle_microduck_lift_demo.py 是另一个扩展版本，本轮没有加载它，组合维度标未知，不能抄用本表。

与新扫地机研究的关系

两种旧车辆提供“支持者移动”的不同实现经验；它们都不提供 Duck 在扫地机上的接触载运、上下车成功率或载荷极限。AOR-013 独立研究这些事实。其现有冻结模型与已写出的分段报告见简化扫地底盘卡，后续研究结论和评审仍由原任务维护；候选来源另见 OOMWOO 条目本地核验记录：docs/robots/CANDIDATES.md。
